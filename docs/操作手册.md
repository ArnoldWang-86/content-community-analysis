### 一个必须知道的坑

B站搜索接口 `search/type` 从 2023 年起要求 **wbi 签名**。**不加签名时接口仍返回 `code=0` 和 20 条数据，但 `page` 参数被静默忽略——翻到第几页都是同一批结果。**

这个坑非常隐蔽：你不会收到任何报错，只会拿到远少于预期的数据。已封装在 `src/bili.py` 里，所有脚本自动处理，**不要绕开它直接用 requests**。

# 阶段 1 · 数据采集（约 15 分钟人工 + 4 小时机器）

## 1.1 接口可用性（实测结论，别再试错的）

| 接口 | 状态 | 用途 |
|---|---|---|
| `x/web-interface/search/type` | **主力数据源**（**必须 wbi 签名**） | 按关键词搜索，50 页 × 20；返回 播放/点赞/收藏/弹幕数/评论数/发布时间/时长/标签/分区。**实测每关键词可得约 700 条唯一** |
| `x/web-interface/view?bvid=` | 可用 | 补 **投币、分享、cid**（cid 用于取弹幕） |
| `x/relation/stat?vmid=` | 可用 | UP 主粉丝数 |
| `x/v1/dm/list.so?oid={cid}` | 可用（XML） | **弹幕文本** → 项目 2 的语料 |
| `x/web-interface/popular` | 可用但仅 ~1000 条 | 备用，量太小 |
| `x/web-interface/ranking/v2` | -352 风控 | 放弃 |
| `x/v2/reply/*` 评论接口 | -352/-403 | **放弃，评论拿不到** |

> **重要结论：评论接口被封，所以项目 2 的文本语料改用「弹幕」。** 弹幕是短文本、意图明确（求推荐/吐槽/催更等），做意图分类反而比长评论更合适。

# 阶段 2 · 清洗与入库（2 小时）

## 2.1 表设计（4 张表）

打开 `sql/01_schema.sql`，核心结构：

```sql
video -- 视频主表：bvid(PK), title, pubdate, pub_hour, pub_weekday,
               -- duration_s, tid, tname, view, like_cnt, coin, fav, share,
               -- danmaku, reply, up_mid(FK)
up_info -- UP主表：mid(PK), uname, follower
video_tag -- 视频-标签（一对多，JOIN 练习点）：bvid, tag
category -- 分区维表：tid(PK), tname
```

> **为什么要拆 4 张表而不是一张宽表？** 因为分析需要多表关联——只保留宽表的话，标签这类一对多关系没法表达，也写不出 JOIN。

## 2.2 清洗规则（写进代码，也是面试谈资）

| 规则 | 理由 |
|---|---|
| `duration` 从 `"1973:5"` 解析成秒 | 原始格式是 分:秒，必须转数值才能回归 |
| `title` 去除 `<em class="keyword">` 高亮标签 | 搜索结果带 HTML 高亮 |
| 按 `bvid` 去重，保留最新一次 | 跨关键词重复 |
| 剔除 `view < 100` 的样本 | 极小样本互动率无统计意义 |
| 互动率做 **1%/99% 分位截尾** | 防止极值主导回归 |
| `pubdate` 同时派生 `pub_hour`/`pub_weekday` | 时段分析的核心字段 |
| 计算派生指标 | `互动率=(like+coin+fav)/view`、`收藏率=fav/view`、`弹幕密度=danmaku/view` |

| # | 分析 | 用到的 SQL 技术 |
|---|---|---|
| 1 | 视频粒度明细宽表 | **4 表 JOIN** |

| 8 | UP 主粉丝量分层 × 互动率 | `CASE` 分箱 + JOIN |
| 9 | 标签与互动率关联 | `video_tag` 展开后聚合 |

# 阶段 4 · 统计检验与建模（3 小时）

```powershell
python src\07_stats_model.py
```

## 4.1 时段效应检验（核心结论）
- 定义"晚间 19–22 点" vs "凌晨 0–6 点"两组
- **先做正态性/方差齐性检验**（Shapiro / Levene）→ 决定用 t 检验还是 Mann-Whitney U
- 输出：**Welch t 检验 p 值 + Cohen's d 效应量**
- 输出：组间差异百分比、Welch t 检验 p 值、Cohen's d 效应量、Bootstrap 置信区间

## 4.2 文本特征
- jieba 分词 + 去停用词
- **TF-IDF** 提取高互动 vs 低互动视频的标题/标签差异词
- 词云图（matplotlib + wordcloud）

## 4.3 分群
- 对标准化后的指标矩阵做 **KMeans**，k 用**肘部法 + 轮廓系数**选
- 输出：k 值、轮廓系数、各簇画像

## 4.4 预测建模
- 目标变量：是否爆文（同分区 Top 5%）
- **逻辑回归**（可解释）+ **随机森林**（性能）
- 5 折交叉验证，输出 AUC / PR-AUC
- **SHAP** 输出特征重要性，用于解释模型

# 阶段 5 · 交互式看板

实际用的是 Plotly。Tableau 的官方下载源对中国 IP 返回 403，Power BI 下载速度也只有 11 KB/s，
具体过程见 README 里的工具选择一节。

1. 连接 MySQL，或先导出 CSV
2. 用 Plotly 生成 8 个模块：KPI 总览、分区互动率、发布时段热力图、小时趋势、粉丝量级、视频时长、内容分群、意图分布
3. 三层结构：
   - **总览**：分区 × 平均互动率
   - **时段热力图**：星期 × 小时的互动率矩阵，最出效果的一张图
   - **结构下钻**：内容分群与意图结构
4. 交互能力：
   - **计算字段**：互动率 =（点赞 + 投币 + 收藏）/ 播放量
   - **分区均值基准**：对应 Tableau 的 LOD 表达式 `{FIXED [分区]: AVG([互动率])}`
   - **筛选联动**：点击图例开关系列
   - **悬浮提示**：展示样本量与精确数值
5. 导出单文件 HTML，发布到 GitHub Pages
